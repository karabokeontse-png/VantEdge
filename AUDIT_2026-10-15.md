## 0. How to read this document

### 0.1 What this is

This is an audit of a codebase that has just completed a significant architectural pivot — three P0
commits moving the analytical authority from the LLM to a deterministic scoring chain (W5). The audit's
primary question was: **did that pivot actually land?**

Short answer: **partially.** The structural enforcement is real and well done (§4.2). But the two
commits that were supposed to fix the *data* feeding the deterministic chain (`96513ba`, `5609322`)
plumbed values that are structurally guaranteed to be empty, so the deterministic chain runs — on
nothing. Two of the three P0 commits are, in production, **inert**.

The audit also found two scoring defects that, independently of the pivot, make the headline product
output (the compatibility score) mathematically incapable of reaching the range the UI advertises.

### 0.2 Method and evidence standard

- **Read-only.** No file in the repository was modified. `git status --short` is empty before and after.
- Every finding below carries a `file:line` reference and, where the finding is about code, a **verbatim
  quotation** of the offending code. Claims are not paraphrased into vagueness.
- Claims that would be damaging if wrong were **independently re-verified** by the auditor after the
  subsystem audits returned. These are marked **[VERIFIED]** and the verification command is shown.
- Dead-code claims were verified by exhaustive `grep` before being asserted, not inferred.

## 4. PART A — The deterministic scoring engine (W5)

### 4.1 [VERIFIED] A1 — `RoleRelevance` is identically `0.0` — P0

**The single most impactful defect in the codebase.**

`JobRequirementAdapter.kt:120` hardcodes the job title to the empty string:

```kotlin
        val validatedJob = toValidatedJob(adaptedInput, "", correlationId)
```

This is the **only** call site of `toValidatedJob` in the entire repository:

```
$ grep -rn "toValidatedJob" --include=*.kt app/src
app/src/main/java/com/vantedge/app/w5/scoring/JobRequirementAdapter.kt:120:        val validatedJob = toValidatedJob(adaptedInput, "", correlationId)
app/src/main/java/com/vantedge/app/w5/scoring/JobRequirementAdapter.kt:402:    fun toValidatedJob(
```

`roleRelevance` derives the job-side token set entirely from that title:

```kotlin
// AxisEvaluators.kt:22-33
    fun roleRelevance(profile: ValidatedProfile, job: ValidatedJob, assets: ValidationAssets): Double {
        val profileTokens = (profile.roles + listOf(profile.currentTitle ?: ""))
            .flatMap { tokenize(it, emptySet()) }
            .toSet()
        val expandedProfile = expand(profileTokens, assets.keywordDictionary)
        val filteredProfile = expandedProfile.filter { it !in assets.stopWords }.toSet()
        val jobTokens = tokenize(job.title, emptySet()).toSet()
        val expandedJob = expand(jobTokens, assets.keywordDictionary)
        val filteredJob = expandedJob.filter { it !in assets.stopWords }.toSet()
        return jaccard(filteredProfile, filteredJob)
    }
```

and `jaccard` returns `0.0` when the union is non-empty and the intersection is empty:

```kotlin
// W5Utils.kt:16-21
fun jaccard(setA: Set<String>, setB: Set<String>): Double {
    val intersection = setA.intersect(setB)
    val union = setA.union(setB)
    return if (union.isEmpty()) 0.0 else intersection.size.toDouble() / union.size
}
```

`tokenize("")` → `[]`. If the profile side is also empty, `union.isEmpty()` → `0.0`.
**Either branch returns `0.0`. `roleRelevance ≡ 0.0`, unconditionally, for every candidate, forever.**

| Regex | Correct word | Becomes |
|---|---|---|
| `\bcl(?=[aeiou])` → `d` | Client, Clean, Claim, Classic | **Dient, Dean, Daim, Dassic** |
| `\bI(?=[a-z])` → `l` | Ireland, Incident, Impact | **lreland, lncident, lmpact** |

non-capturing.

## 14. Open questions requiring a product decision

These are not defects I can prescribe a fix for. Each needs an explicit decision from the team, and each
one currently has the code answering a question nobody asked on purpose.

1. **Is the compatibility score supposed to be comparable across candidates, or a coaching signal?**
   The current design mixes both: `ConstraintCompliance` is a data-quality gate, `skillMatch` is Jaccard
   (which penalises breadth), and `keywordCoverage` returns `1.0` for an empty keyword list (a vacuous
   pass). If it is a coaching signal, Jaccard is wrong for `skillMatch` — an F1 or a coverage measure
   rewards breadth correctly. This choice changes A1's fix, A2's replacement axis, and the threshold
   recalibration together.

2. **Should a missing requirement (`requiredYears == null`) be neutral or penalising?**
   Currently penalising at 20 % of the score. For a job post that does not state a years requirement,
   that is a systematic bias against less-exienced candidates — arguably the opposite of what the product
   is for. **This is a fairness decision, not a bug fix.**

3. **Is the AI narrative advisory or load-bearing?**
   Currently neither: it is required for the score to be computed (A7), its absence is invisible (A33),
   and it is never shown with an integrity annotation. The three options — (a) always compute W5 first and
   enrich asynchronously, (b) block on the narrative, (c) remove narrative entirely — have very different
   cost and UX profiles.

4. **Is `ContractValidator` a gate or advisory?**
   If gate: the five bypass paths in §7.1 are P0. If advisory: delete it rather than let it imply a
   guarantee it does not provide.

5. **Should user CV data be cloud-backed-up?** For an employment dossier, `allowBackup="false"` is the
   defensible default — but if users expect their profile to survive a device change, that is a product
   decision with a cryptographic-escrow design behind it, not a manifest flag.

6. **Which model tier?**
   Both configured models are `:free` (`nvidia/nemotron-3-super-120b-a12b:free`,
   `cohere/north-mini-code:free`). The code has already been burned by this: commits `70ef4ee`, `29bd88a`,
   and `77be059` are three consecutive attempts to work around reasoning models exhausting the token
   budget and returning `content:null`. Free-tier latency and the 120 s budget are the direct cause of
   A7 and A28. **Paid models would make several P1 findings disappear.**

7. **Is the W6 improvement engine in scope?** 420 lines of tests, zero production callers. Either commit
   to wiring it or delete it — an unreachable engine with good tests creates a false sense of coverage.

### 15.3 Where I may have been too soft

- I graded the **dead code** as P2/P3. It may deserve more: ~2,400 LOC of dead screens plus ~780 LOC of
  dead domain code plus 100 % of two packages is roughly **18 % of the codebase** that no user can reach.
  Every future change has to read it to rule it out. If the team does not commit to a deletion pass, I
  think the codebase will not converge.
- I treated **`versionCode 1`** as hygiene (P1 under A43). For a sideloaded app with no store, it may be

- I may have **underweighted the `compatibility` pipeline's 120 s serial AI gate** (A7). For the user

  architecture" rather than "P0 performance".
